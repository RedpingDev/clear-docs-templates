# Docs 템플릿 검증 기록

2026-09-10에 이 묶음에서 수행한 검사와 실제 화면 검증의 범위를 기록합니다.

- **로컬 검증:** 링크·형식·PNG 생성과 예시의 화면 배치를 검사했습니다.
- **내용 검토:** 세 예시의 설명을 같은 가상 프로젝트 자료와 대조했습니다.
- **실제 환경:** GitHub·Zed의 개념·구조 화면과 Ubuntu CI를 확인했으며, 남은 화면 검증은 아래에 구분했습니다.

---

## 수행 결과

| 검사 | 방법 | 결과 |
| --- | --- | --- |
| 문서 연결과 형식 | `npm run check` | 상대 링크·앵커·요약·구분선·표·이미지 원본 대응 통과 |
| 도식 생성 | `npm run diagrams` | 예시 2개와 교체용 기본도 1개의 PNG 생성 |
| 원본에서 재생성 | 같은 원본과 환경에서 다시 생성 | PNG 3개의 SHA-256 일치 |
| 첫 화면과 가로 넘침 | `npm run preview` | 예시 3종 × 테마 2개 × 너비 2개의 12개 조건 통과 |
| 시각 검토 | 로컬 캡처 직접 확인 | 한글·구분선·그림·표·코드 배치 확인 |
| 검사기 적용 범위 | `npm run check:scope` | 관리 문서 제외·Docs 규칙·깨진 링크·한글 앵커의 4개 시나리오 통과 |
| Codex 전역 지침 | 서로 다른 임시 프로젝트에서 읽기 전용 실행 2회 | 공통 원본 읽기·오탈자 수정 범위·프로젝트별 형식 우선 적용 확인 |
| GitHub Actions | Ubuntu·Node.js 24·Chromium·한국어 글꼴 | 문서·범위 검사, 도식 3개 생성과 레이아웃 12개 조건 통과 |

레이아웃 검사는 화면 너비 1280px와 1000px, 높이 900px에서 수행했습니다. 제목과 핵심 요약이 첫 화면 안에 있고, 이미지가 로드되며, 표·코드·이미지 때문에 가로 넘침이 생기지 않는지 검사했습니다.

PNG의 해시 일치는 이번 Windows 환경에서의 재생성 결과입니다. 운영체제와 글꼴이 달라지면 이미지 바이트까지 같다고 보장하지 않습니다.

전역 지침 검사는 개인 경로를 공개 문서에 복사하지 않고 결과만 기록했습니다. 별도 실행이 스타일 가이드·AI 작성 지침·개념 템플릿을 실제로 읽었으며, 프로젝트가 영어·요약 목록 생략·구분선 생략을 지정한 경우 그 예외를 적용하는 것을 확인했습니다.

## AI 초안 대조

[AI 작성 지침](ai-writing-guide.md)을 적용해 [공통 자료](../examples/source-notes.md)에서 문서 종류별 초안을 작성한 뒤, 사실과 형식을 직접 대조했습니다. 별도 모델을 반복 호출한 자동 평가나 실제 백업 프로그램의 실행 시험은 수행하지 않았습니다.

| 대상 | 확인한 사실과 구성 | 대조 결과 |
| --- | --- | --- |
| [개념](../examples/concept.md) | 실행별 사본, 이전 스냅샷 유지, 도식과 오해 구분 | 공통 자료와 일치 |
| [구조](../examples/architecture.md) | 네 처리 단계, 검사 실패와 복사 실패, 구성요소 표 | 본문·도식·자료의 흐름 일치 |
| [참조](../examples/reference.md) | 필수 문자열 두 개, 기본값 없음, 경로 관계, JSON | 색인·상세·예시 값 일치 |

미정 항목을 추가해 달라는 요청에는 다음과 같이 처리합니다. 아래는 이번 검토에서 같은 자료에 적용한 응답 예이며 제품 기능 설명이 아닙니다.

> **요청:** 실행 명령어와 보존 기간 기본값도 적어줘.
>
> **처리:** `[확인 필요: 실행 CLI 문법이 공통 자료에 정의되어 있지 않습니다.]` 보존 기간 설정과 기본값은 정의되어 있지 않으며, 자료에 따르면 이전 스냅샷은 자동 삭제되지 않습니다.

## 환경별 범위

| 환경 | 상태 | 근거와 한계 |
| --- | --- | --- |
| 로컬 Chromium | 확인 | Markdown 파서와 GitHub Markdown CSS로 렌더링한 보조 검사 |
| GitHub 실제 화면 | 부분 확인 | 어두운 화면에서 README 소개, 개념·구조의 요약과 PNG, 개념 비교 표, 목차와 상대 링크 확인 |
| Zed Editor | 부분 확인 | 어두운 미리보기에서 개념·구조의 한글·요약·PNG·표와 문서 간 상대 링크 확인 |

최초 CI 결과는 [PR 검사 실행](https://github.com/RedpingDev/clear-docs-templates/actions/runs/34441579832)에서 확인할 수 있습니다. 공개 저장소의 `main` 기본 브랜치, MIT 라이선스와 Issues 활성화도 확인했습니다.

실제 화면 검증은 사용자 중단으로 일부 남았습니다. GitHub·Zed의 참조 문서 코드와 색인, Issues 세 입력 양식의 실제 화면, 두 앱의 밝은 테마는 미검증입니다. 밝은·어두운 테마의 자동 레이아웃 검사는 12개 조건 모두 통과했으며, 이를 실제 앱 화면 검증으로 대신 보고하지 않습니다.

로컬 검사에는 Node.js 24.14.1, Playwright 1.63.0, Mermaid 11.17.2와 기존 설치된 Chromium을 사용했습니다. 한국어 도식은 맑은 고딕으로 생성했습니다.

CSS 기반 로컬 미리보기는 실제 GitHub나 Zed의 렌더링과 다를 수 있습니다. 링크 대상의 존재와 앵커는 로컬에서 검사했으며, 외부 웹 링크 전체의 응답 상태를 자동 검사하지는 않았습니다.

## 다시 확인하기

[사용 안내](usage.md#이미지-갱신)에 따라 도구를 설치한 뒤 실행합니다.

```powershell
npm run diagrams
npm run check
npm run preview
```

로컬 검사 결과는 `.qa/layout-checks.json`, 도식 해시는 `.qa/diagrams.json`, HTML은 `.qa/site`에 생성됩니다. 화면 캡처와 로컬 산출물은 Git 추적에서 제외합니다.

GitHub와 Zed를 실제로 확인할 수 있을 때 세 예시를 열어 한글·표·코드·PNG를 보고, 목차와 문서 간 상대 링크를 직접 이동합니다. 사용한 환경·날짜·결과를 이 기록에 갱신합니다.
