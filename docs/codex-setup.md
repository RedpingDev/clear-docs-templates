# Codex 전역 적용

이 템플릿 저장소를 같은 Codex 홈을 사용하는 여러 프로젝트의 문서 작성 기본값으로 연결합니다.

- **공통 원본:** 템플릿 저장소를 유지할 로컬 폴더에 복제합니다.
- **적용 조건:** README와 개념·구조·참조 Docs를 새로 쓰거나 개편할 때 사용합니다.
- **저장 위치:** 작성한 문서와 필요한 그림은 각 프로젝트 안에 저장합니다.

**바로가기:** [원본 준비](#원본-준비) · [전역 지침 등록](#전역-지침-등록) · [적용 범위](#적용-범위) · [확인과 갱신](#확인과-갱신) · [다른 환경과 해제](#다른-환경과-해제)

## 원본 준비

프로젝트와 별도로 유지할 로컬 폴더에 저장소를 복제합니다. 폴더의 절대 경로를 기록해 다음 단계의 지침에 넣습니다.

```bash
git clone https://github.com/RedpingDev/clear-docs-templates.git
```

문서 작성에 필요한 원본은 [스타일 가이드](style-guide.md), [AI 작성 지침](ai-writing-guide.md), [개념](../templates/concept.md)·[구조](../templates/architecture.md)·[참조](../templates/reference.md) 템플릿입니다. 도식 도구 설치는 [이미지 갱신](usage.md#이미지-갱신)을 참고하세요.

## 전역 지침 등록

Codex 홈의 `AGENTS.md`를 먼저 백업하고 기존 내용을 유지한 채 아래 구역을 추가합니다. 기본 위치는 `~/.codex/AGENTS.md`이며 `CODEX_HOME`을 지정했다면 해당 폴더를 사용합니다.

`AGENTS.override.md`가 있으면 전역 `AGENTS.md`보다 우선하므로, 현재 활성 지침을 확인한 뒤 적용 위치를 정합니다. [Codex 공식 지침 탐색 설명](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

아래 `<템플릿 저장소의 절대 경로>`를 실제 로컬 경로로 바꿉니다. 공백이 있는 경로도 끝까지 포함합니다.

```markdown
## 기본 문서 양식 — Clear Docs Templates

- 공통 템플릿 원본: `<템플릿 저장소의 절대 경로>`.
- README를 새로 작성하거나 개편할 때 Best-README-Template의
  구성을 사용한다. 참고: https://github.com/othneildrew/Best-README-Template
- 개념·구조·참조 Docs를 새로 작성하거나 개편하기 전에 공통 원본의
  `docs/style-guide.md`, `docs/ai-writing-guide.md`와 해당
  `templates/concept.md`, `templates/architecture.md`,
  `templates/reference.md` 중 필요한 템플릿을 실제로 읽는다.
- 목적 한 문장과 핵심 2~3개를 먼저 보여주고, 주요 구역은 구분선으로
  나눈다. 상세는 펼쳐두며 문서 종류별 본문 순서를 따른다.
- 작성한 문서·PNG·도식 원본은 작업 중인 프로젝트에 저장한다.
  문서 내부 링크는 해당 프로젝트 안의 상대 경로를 사용한다.
- 단순 오탈자 수정은 기존 구성을 유지하고 전체 문서를 재구성하지 않는다.
  기존 문서의 일괄 변환은 요청받았을 때만 수행한다.
- AGENTS.md, 이슈·PR 양식, 변경 기록 등 용도가 다른 Markdown에는
  Docs 양식을 강제하지 않는다.
- 사용자의 명시적 요청과 프로젝트별 지침을 함께 확인한다.
  프로젝트별 문서 규칙이 있으면 해당 범위에서 그 규칙을 우선한다.
- 자료에 없는 동작·설정·설계 이유를 만들지 않는다.
  미확인 정보는 [확인 필요: 내용]으로 표시한다.
- 원본 경로에 접근하지 못하면 접근 불가를 알리고, 템플릿을 읽거나
  적용을 검증했다고 보고하지 않는다.
- 원격 저장소를 작업마다 자동으로 내려받지 않는다.
```

## 적용 범위

| 요청 | 기본 동작 |
| --- | --- |
| 새 개념·구조·참조 문서 작성 | 공통 가이드와 해당 템플릿을 읽고 작성 |
| 기존 문서의 본격적인 개편 | 기존 사실과 링크를 보존하며 양식 적용 |
| 오탈자 한 곳 수정 | 해당 내용만 수정하고 구조 유지 |
| 프로젝트가 별도 문서 형식을 지정 | 그 프로젝트의 구체적인 규칙 확인·적용 |

전역 지침은 문서 작성 시 사용하는 기본값입니다. 등록 자체가 기존 프로젝트의 파일을 바꾸거나 이미 진행 중인 작업에 즉시 지침을 다시 로드한다는 뜻은 아닙니다.

## 확인과 갱신

새 Codex 실행에서 ‘현재 문서 작성 지침과 공통 원본 경로를 확인하고 실제 읽을 파일을 알려줘’라고 요청합니다. 읽기 전용으로 가이드와 템플릿을 확인하고 오탈자 수정과 새 문서 작성의 차이를 설명하는지 확인합니다.

이 저장소의 변경을 검토한 뒤 로컬 원본을 갱신하면 이후 문서 작성부터 바뀐 양식을 사용합니다. Git으로 관리할 때는 작업 내용을 먼저 정리한 뒤 원본 저장소에서 실행합니다.

```bash
git switch main
git pull --ff-only
```

고정 버전을 쓰려면 별도의 복제본에서 릴리스 태그를 선택하고 그 복제본을 원본 경로로 지정합니다. 일반 사용 중에는 현재 브랜치나 로컬 변경 사항을 자동으로 전환하지 않습니다.

## 다른 환경과 해제

다른 PC나 클라우드 작업에는 템플릿 원본과 지침을 별도로 준비해야 합니다. 이 PC의 절대 경로는 다른 환경에서 자동으로 연결되지 않습니다.

적용을 해제하려면 전역 파일에서 `기본 문서 양식 — Clear Docs Templates` 구역만 제거합니다. 다른 지침은 보존하고 새 실행에서 적용 상태를 확인합니다.
