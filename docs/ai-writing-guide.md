# AI 초안 작성 지침

근거 자료에서 일관된 Docs 초안을 만들고 사람이 검토하는 절차입니다.

- **종류 선택:** 개념·구조·참조 중 독자의 주된 질문에 맞춥니다.
- **근거 우선:** 동작·설정·설계 이유는 제공한 자료로 확인합니다.
- **검토 가능:** 미확인 사항과 수정할 이미지 원본을 명확히 남깁니다.

**바로가기:** [입력 준비](#입력-준비) · [작성 순서](#작성-순서) · [재사용 요청문](#재사용-요청문) · [사람의 검토](#사람의-검토) · [예시로 점검](#예시로-점검)

---

## 입력 준비

선택한 템플릿, [스타일 가이드](style-guide.md), 프로젝트 자료를 함께 제공합니다. 자료에는 현재 적용할 버전이나 범위를 알 수 있는 정보를 포함합니다.

파일이나 링크의 내용에 접근할 수 없다면 AI가 읽었다고 가정하지 않습니다. 필요한 부분을 직접 제공하거나 접근 불가로 표시하게 합니다.

---

## 작성 순서

1. 독자가 답을 얻으려는 질문으로 문서 종류를 정합니다. 종류를 지정했다면 그 선택을 따릅니다.
2. 입력 자료에서 확정된 동작·설정·조건을 정리하고 모순이나 누락을 구분합니다.
3. 템플릿의 목적과 핵심 요약을 먼저 작성한 뒤 본문을 채웁니다.
4. 구조 문서는 전체 구조도 원본을 작성하고 PNG로 생성합니다. 개념 문서는 도식과 사례 중 적합한 것을 선택합니다.
5. 사실, 형식, 링크, 이미지와 본문의 일치 여부를 점검합니다.

자료에 없는 기본값·명령어·파일 경로·실패 처리·설계 이유를 만들지 않습니다. 자료가 충돌하면 임의로 하나를 선택하지 말고 충돌 지점에 `[확인 필요: 충돌 내용]`을 남깁니다.

PNG를 생성할 수 없는 환경에서는 원본만 만들었다고 알리고, 본문에 `[확인 필요: PNG 생성]`을 표시합니다. 존재하지 않는 이미지를 생성 완료로 보고하거나 깨진 이미지 링크로 대신하지 않습니다.

## 재사용 요청문

아래 요청문을 복사하고 입력 항목을 채웁니다. 선택한 템플릿과 스타일 가이드의 실제 내용도 함께 전달하세요.

```text
목적: 근거에 충실하고 핵심이 먼저 보이는 Docs 초안을 작성한다.

입력
- 프로젝트와 적용 범위: {{프로젝트, 버전 또는 기준 시점}}
- 독자의 질문: {{이 문서에서 답할 질문}}
- 문서 종류: {{개념 / 구조 / 참조 / 질문에 맞춰 선택}}
- 출력할 문서 위치: {{프로젝트 내부 경로}}
- 템플릿: {{선택한 템플릿의 내용 또는 접근 가능한 파일}}
- 스타일 가이드: {{가이드 내용 또는 접근 가능한 파일}}
- 근거 자료: {{코드, 설정, 기존 문서 또는 확인된 메모}}

작성 규칙
1. 제목 → 목적 한 문장 → 핵심 2~3개 순서로 시작한다.
2. 본문은 선택한 템플릿의 순서를 따르고 상세는 펼쳐둔다.
3. 주요 ## 구역 사이에 ---을 두고 ###까지 사용한다.
4. 본문 ## 구역이 5개 이상이면 요약 뒤에 짧은 목차를 둔다.
5. 문단은 한 가지 내용과 기본 2~3문장, 표는 기본 4열 이내로 쓴다.
6. 구조 문서에는 전체 구조도를, 개념에는 도식 또는 사례를 둔다.
7. 그림은 PNG와 같은 이름의 .mmd 원본을 함께 제공한다.
   그림 아래에 한 문장 해석을 적고 대체 텍스트를 제공한다.
   필수 관계는 본문에도 적는다. PNG 미생성 상태는 명시한다.
8. 제공 자료에 없는 동작·설정·설계 이유를 추측하지 않는다.
   누락·모순은 [확인 필요: 구체적인 내용]으로 표시한다.
9. 실제 존재하는 상대 링크만 사용하고 제목 앵커를 확인한다.
10. 완성된 부분의 자리표시자와 작성 안내 주석을 제거한다.

출력
- 문서 Markdown과 필요한 이미지·수정용 원본.
- 문서 본문과 분리된 검토 메모:
  선택한 종류, 사용한 근거, 미확인 사항, 이미지 생성 여부,
  수행한 검사와 수행하지 못한 검사.
```

## 사람의 검토

- 제목·목적·요약만 읽고 무엇을 얻는 문서인지 설명할 수 있는지 확인합니다.
- 설정 기본값과 실패 동작 등 중요한 문장을 원자료와 대조합니다.
- `[확인 필요: ...]`를 해결하거나 미정이라는 설명으로 남깁니다.
- 그림이 설명을 돕는지, 그림 없이도 필수 관계를 이해할 수 있는지 확인합니다.
- GitHub와 Zed에서 링크·한글·표·코드·이미지를 확인하고 미검증 환경을 구분합니다.

검토를 마치면 Markdown과 변경한 도식 원본·PNG를 함께 저장합니다. 검토 메모를 제품 동작 설명 속에 섞지 않습니다.

## 예시로 점검

[예시용 공통 자료](../examples/source-notes.md)를 같은 입력으로 사용하고 문서 종류만 바꿔 세 초안을 만듭니다. 입력에 완성 예시를 넣지 않아야 자료만으로 초안을 만드는 과정을 점검할 수 있습니다.

| 점검 대상 | 기대하는 결과 |
| --- | --- |
| 개념 초안 | 이전 스냅샷 유지, 실행 시점의 사본, 동기화와의 구분을 설명합니다. |
| 구조 초안 | 설정 읽기·입력 검사·파일 복사·결과 보고와 실패 흐름을 연결합니다. |
| 참조 초안 | `source`, `destination`을 필수 문자열·기본값 없음으로 설명합니다. |
| 미정 정보 추가 요청 | CLI 문법이나 보존 기간을 추측하지 않고 확인 필요로 표시합니다. |

완성 예시 3종은 이 절차로 작성한 기준본입니다. 구조와 사실은 비교하되 문장이 똑같아야 할 필요는 없습니다.
